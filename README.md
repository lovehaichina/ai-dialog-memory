# AI Dialog Memory · 历史对话自动存档与召回

> 给 AI 助手加一套轻量的"长期记忆"：每次对话自动存档、每日批量提炼索引、新对话自动召回相似历史任务。

## 这是什么？

一套基于**提示词驱动**的对话记忆机制，不需要额外软件、不需要向量数据库、不需要写代码——只需要：

1. 一段全局提示词（贴到你的 AI 助手的 AGENTS.md 或系统提示里）
2. 几个本地文件（JSON 水位表 + Markdown 存档 + 语义索引）
3. 一个每日定时任务（把当天存档提炼成语义索引）

每次新对话开始时，AI 自动查索引找相似历史任务；对话结束时自动判断是否需要存档。这样无论新开窗口还是老窗口继续聊，历史经验都不会丢。

## 核心思路

```
每次对话第一句
    │
    ├─ 召回：读 INDEX-SEMANTIC.md → 找相似历史任务 → 引入上下文
    │
    └─ 存档判断：读 windows-map.json → 查当前窗口上次存档时间
            │
            ├─ 今天已存过 → 跳过
            ├─ 今天没存过 → 把上次到现在的对话写成 md 存档 → 更新时间戳
            └─ 新窗口 → 新建存档
```

```
每日定时任务（17:30）
    │
    └─ 扫当天新增的 md → 提炼主题摘要 → 追加到 INDEX-SEMANTIC.md
```

## 目录结构

```
your-memory/
├── windows-map.json          # 窗口水位表（哪个窗口最后存档时间）
├── INDEX-SEMANTIC.md         # 语义索引（每日自动提炼）
├── INDEX.md                  # 按月索引（可选）
├── YYYY/
│   └── MM/
│       └── YYYY-MM-DD-<主题>.md   # 每天的对话存档
└── PITFALLS.md               # 踩坑记录（可选，另一个机制）
```

## 快速开始

### 第 1 步：建目录

选一个你喜欢的位置（比如 `D:\ai-memory\`），建好上面的目录结构。

### 第 2 步：复制模板

把 `templates/` 下的三个文件复制到你的记忆库根目录：

- `windows-map.json` — 初始化为空 `{"windows":{}}`
- `INDEX-SEMANTIC.md` — 空模板
- `archive-template.md` — 存档模板（参考用）

### 第 3 步：贴全局提示词

把 `AGENTS.md` 里的「历史对话自动存档与召回机制」段落贴到你的 AI 助手全局指令里。**注意把路径改成你自己的路径**。

### 第 4 步：建每日定时任务

创建一个每天定时跑的任务（比如每天 17:30），让 AI 做：

1. 扫当天新增的存档 md
2. 每个文件提炼一行：日期 | 主题 | 一句话摘要 | 文件路径 | 关键词
3. 追加到 `INDEX-SEMANTIC.md`

具体配置见 [`cron-setup.md`](cron-setup.md)。

### 第 5 步：验证

- 新开一个对话，说句话 → 检查记忆库里是否新建了存档
- 同一天再开一个对话 → 检查是否跳过（因为今天已存过）
- 第二天再对话 → 检查是否把昨天到今天的增量补存了
- 等定时任务跑完 → 检查 `INDEX-SEMANTIC.md` 是否有内容

## 存档文件格式（9 字段）

每个存档文件里，每个主题一组：

| 字段 | 说明 |
|---|---|
| 任务目标 | 这次对话要解决什么问题 |
| 关键决策 | 做了哪些判断、选了哪个方案、为什么 |
| 执行结果 | 最终产出了什么、结论是什么 |
| 涉及文件 | 产出的文件路径（本地路径写绝对路径，识别不到写"见对话第X轮"） |
| 图片附件 | 截图/图片路径或说明 |
| 待办 | 还没做完的事、下次要继续的 |
| 可复用经验 | 下次类似任务能直接用的方法/结论 |
| 新踩坑 | 这次新发现的坑（if-then 格式） |
| 来源引用 | 参考的文档/链接/对话 |

如果一次对话里有多个主题，一个文件里写多组 9 段。

## 设计决策（为什么这么做）

1. **为什么不实时存档？** 实时存档会打断对话节奏，而且很多对话是寒暄/问答不需要存。每天判断一次足够。
2. **为什么不存完整对话原文？** 完整对话太长，AI 读不动。提炼成 9 字段结构化摘要，召回时一眼就能看懂。
3. **为什么召回不读本窗口存档？** 老窗口里 AI 自己有上下文，再读存档是重复信息。召回只做一件事：找**跨窗口**的相似历史任务。
4. **为什么定时任务不在对话里做？** 对话时 AI 专注解决当前任务，索引提炼是批量工作，放晚上统一跑。
5. **为什么聊完就关的窗口接受漏存？** 这种窗口大概率不会再打开，不值得为此加补存逻辑。

## 局限性

- **依赖 AI 自觉执行**：全靠提示词驱动，AI 如果没遵守提示词就会漏存
- **召回靠语义匹配**：不是向量检索，是 AI 读索引后自己判断相似度，效果取决于模型能力
- **绑定本地文件系统**：需要 AI 能读写本地文件（豆包工作/Claude Desktop 等支持 MCP 的环境可用）
- **没有自动化脚本**：所有动作由 AI 在对话中完成，不是代码自动跑

## 适用场景

- 用 AI 做长期项目管理，希望新对话能想起之前的结论
- 每天和 AI 聊很多不同话题，希望按主题归档
- 踩过的坑不想再踩，希望每次对话前自动提醒
